## Собственный IP-endpoint — 15.10.2026

Браузерная диагностика использует `https://orbit.server-uniofweb.ru/_orbit/ip/`.
Endpoint работает в Apache/PHP независимо от Next.js и БД. Для первой установки
от имени www-data скопировать `deploy/ip-check.php` в
`/var/lib/orbit/ip-check/ip-check.php` (каталог 750, файл 640). Администратору
проверить PHP-модуль, политику доверия mod_remoteip и применить соответствующий
Alias/ProxyPass из `deploy/apache-orbit.conf` с configtest и graceful reload.
Не доверять произвольному X-Forwarded-For; обязательна публичная проверка с
поддельными XFF/Forwarded/X-Real-IP. Альтернативный шаблон непосредственного TLS
на nginx возвращает `$remote_addr` без PHP.

На текущем origin обратное подключение к своему публичному TLS адресу недоступно.
Поэтому `WORKER_DIRECT_IP_CHECK_URL` оставляет прежний URL только для отдельного
прямого сравнения Node.js. IP Chromium измеряется в контексте задачи через свой
прокси; это измерение не заменяется результатом Node.js. Режим warn/required/off,
ограничение ожидания и один повтор временной ошибки сохранены.

Схема БД не меняется. Для отката восстановить два URL из защищённой копии `.env`
и переключить релиз; endpoint можно оставить как независимую диагностику.
Протоколы проверок и копии конфигурации: `/var/lib/orbit/backups/self-ip-20261015/`.

## Supervisor в текущем контейнере

Node.js 22.23.2 установлен в `/opt/node-v22.23.2-linux-x64`, команды доступны
через `/usr/local/bin`; pnpm — 11.19.0. Подготовка кода выполняется от www-data.


упавший веб-процесс, cron запускает Supervisor после загрузки и проверяет его
каждую минуту. Это учитывает сохранённый `crond.reboot` Docker-контейнера.

контейнера этот каталог и код должны сохраняться томом или резервной копией.

## Приёмка

- HTTP домена перенаправляется на HTTPS, сертификат валиден.
- Без cookies `/` → `/login/`, `/api/projects/` → 401.
- После входа доступны все разделы, создание/изменение проекта и выход.
- API ключей, профилей, запуска и снимков без сессии возвращают 401.
- Cookie имеет HttpOnly, Secure и SameSite=Lax; чужой Origin отклоняется.
- Chromium успешно запускается от www-data; проверить Live View на согласованной
  тестовой задаче. Для реальных запусков нужны действующие прокси и ключи
  соответствующих интеграций, они задаются в панели.
- После перезапуска службы учётная запись, проекты и профили сохраняются.
- `journalctl -u orbit.service` и `/var/lib/orbit/runtime/project-worker.log`
  доступны для диагностики. Настроить ротацию журнала исполнителя по объёму.

Для отката остановить службу, вернуть предыдущий `current` и запустить службу.

может потребоваться восстановление согласованной резервной копии.

прокрутке; совместимые click/mouse-события после тапа являются поведением браузера.

проверки сайта. В журнале прогрева записываются способ прокрутки, направление и
число жестов без содержимого страницы. Короткие локальные QA-планы используют
10 действий с небольшой прокруткой; настоящий жест занимает время и учитывается
в прежнем ограничении длительности. Сценарии на 1–5 минут остаются в своих пределах.

## Динамические датчики движения (05.10.2026)

## TCP-пресеты каналов MobileProxy (05.10.2026)

Релиз `/var/www/orbit/releases/20261005-tcp-presets` добавляет кнопку «TCP-пресет»

Пресет выбирается пользователем; установка релиза не меняет настройки провайдера.

ProxyTcpChannel хранит желаемый пресет, его сетевые параметры, поколение и
последнюю диагностику. Все известные порты / алиасы одного providerProxyId
привязываются к одной записи. Дополнительно сохраняются блокировки канала,
одинаковых ссылок ротации и физического модема. Настройка, добавление новых портов
и изменения соединения проверяют принадлежность провайдеру. Конфликт разных
модемов в одном объявленном канале отклоняется.

Применение резервирует канал транзакцией до обращения к API; активные shared-
сеансы и основные задачи дают 409. Новые сеансы во время применения не запускаются.
После принятия запроса статус «Ожидает подтверждения»: доставка занимает до минуты.
Перед браузером лидер параллельного прогрева делает ротацию и одну проверку TCP;
остальные участники ждут его. Проверяется текущий profile_id и реальные показания
относительно выбранного пресета, а не ожидаемого значения из старого кэша API.
Снятые до применения показания не подтверждают новый выбор. Кэш провайдера
может жить 60 секунд; ожидание ограничено, остановка проверяется каждую секунду.
Ошибки канала исключают его из новых назначений. Профили другой ОС остаются
в очереди и могут использовать совместимый канал. Native OS не доказывает ОС.

Диагностика показывает девять TCP-параметров, оценку ОС, время запроса и признак
кэша. TTL сравнивается с учётом distance; MSS допускает снижение оператором до
100 байт. IP, порты, служебные URL и учётные данные диагностики не сохраняются.
Браузер получает только безопасные данные, запросы API используют Bearer-заголовок.
