# Проекты и связи задач

## Реализовано

- `/projects/`: CRUD проектов и поиск по имени, URL, региону.
- `/projects/{id}/`: создание и редактирование задач этого проекта, прогресс и последние 100 записей истории профилей.
- `Project.targetUrl`, строковый `yandexRegionId`, `createdAt`, `updatedAt`.
- `Task.projectId`, `targetExecutions`, `currentExecutions`; `targetDomain` удалён из модели и API. Целевой домен определяется из проекта.
- `Profile.status`: `new`, `warming_up`, `ready`, `banned`; `warmupScore` обновляется после успеха.
- `ProfileProjectHistory`: `id`, `profileId`, `projectId`, `executedAt`, обратные связи. Дополнительное поле `source` маркирует импорт.
- Выключение профиля (`isEnabled`) сохранено независимо от статуса. Удаление задач не удаляет историю. Проект с задачами или историей защищён от удаления.

## Перенос данных

Миграция `20260929020000_task_project_architecture` переносит executionsCount в currentExecutions, а executionLimit в targetExecutions. Если старый лимит неизвестен или меньше уже выполненного количества, новый план равен максимуму старого счётчика и 1. Задачи, уже исчерпавшие план, получают completed.

Для старых целевых задач без проекта создаются проекты «Импорт · …». Их адрес — старый целевой домен, иначе URL задачи. Неизвестный регион получает 213: параметры импортированных проектов следует проверить. Задачи прогрева остаются вне проектов, поэтому projectId nullable в схеме, но обязателен в API для target.

Старый active преобразуется в new/ready/warming_up по данным профиля и задачам. paused переносится в isEnabled=false. UUID и файлы сессий остаются прежними; баллы прогрева переносятся из старых успешных счётчиков warmup-задач.

В историю переносятся использованные назначения с usedAt и задачи с подтверждённым ненулевым счётчиком. Простые резервирования не считаются выполнением. Для старых задач точная дата выполнения неизвестна: executedAt содержит время импорта, source=legacy. Такие записи подписаны в интерфейсе.

## Исполнение

У исполнителя изменена привязка к полям и учёт результатов. Браузерные сценарии оставлены прежними; автоматическое назначение множества профилей по количеству выполнений не добавлено. Поисковый сценарий завершает задачу после одного успешного сценария; при оставшемся плане доступна ручная постановка в очередь.

## Проверки

`pnpm build`, `pnpm test:architecture`, локальные `pnpm test:api`, `pnpm test:worker`, проверка интерфейса Chromium на desktop и мобильном экране. Внешние сайты и платные API во время проверки не используются.
