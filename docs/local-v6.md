# Генератор паспортов local-v7

Новые паспорта получают `generation.version: "6"` и `adapter: "local-v7"`.
Платформа остаётся `Linux armv81`. По настройке эмуляции ARM64 в этом поколении
Client Hints передают `architecture: ""`, `bitness: "64"`, `wow64: false`.
Разрядность здесь — выбранное значение эмуляции, не измерение физического телефона.

Цветовая схема определяется SHA-256 от `color-scheme:${seed}`: вероятность
`light` — 65%, `dark` — 35%. Это распределение, а не квота каждой партии.
Тема сохраняется в паспорте и применяется к контексту браузера. Для старых
паспортов без preferences сохраняется прежняя тёмная тема.

Для ru-RU языки: `ru-RU, ru, en-US, en`; Accept-Language:
`ru-RU,ru;q=0.9,en-US;q=0.8,en;q=0.7`. Заголовок согласован с основным
документом, фреймами, всплывающими окнами и перенаправлениями.

GREASE использует алгоритм Chromium с 11 разделителями, тремя версиями
и перестановкой брендов по мажорной версии. При квалификации читаются
реальные brands/fullVersionList бинарника; они используются при первом
связывании нового паспорта с runtime. Значения ОС и оборудования из
настольного контекста при этом не копируются.
Источник алгоритма: https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/embedder_support/user_agent_utils.cc

`generateMobileProfile()` удалён. Отсутствующий файл сессии сам по себе
не создаёт случайную идентичность: паспорт создаёт `ensurePassport()`.
Существующие паспорта и снимки не мигрируют. При первом связывании старого
неиспользованного паспорта сохраняется прежний формат метаданных.

Проверки: `tests/local-v6.test.mjs`, тесты каталога, восстановления сессий,
исполнителя и `tests/device-catalog-ui.mjs`. Проверка браузера включает
обе темы, пять типов документов и повторное открытие контекста.

В отчёт проверки версии 5 добавлена `contextMatrix`: основной документ,
same-origin и cross-origin iframe, DedicatedWorker, SharedWorker и ServiceWorker.
В каждом контексте измеряются доступные параметры Navigator, Client Hints,
часовой пояс, WebGL/WebGL2 и OffscreenCanvas. Обычный Canvas и OffscreenCanvas
сравниваются с одинаковой заливкой в основном документе. Данные Worker собираются
в начале его скрипта, а не после выполнения сценария сайта.

Матрица работает в диагностическом режиме (`enforcement: "diagnostic"`):
расхождения сохраняются с ожидаемыми и фактическими значениями и добавляют
предупреждение, но пока не меняют допуск профиля к работе. Отсутствующие
необязательные API отмечаются как `unsupported`, ошибки и тайм-ауты измерения —
как `error`. Успешный основной статус проверки не означает успешную матрицу;
её результат хранится отдельно в `contextMatrix.status`.

Ресурсы матрицы обслуживаются локальными маршрутами Playwright, без внешних
сайтов и рабочего прокси. У каждой проверки собственный scope ServiceWorker;
регистрация удаляется после измерения. Квалификация Chromium сохраняет сводку
матрицы и полные отчёты контрольных устройств. Код матрицы входит в ключ кэша
квалификации, поэтому старое одобрение не подменяет новое измерение.
Регрессионные проверки: `tests/context-matrix.test.mjs`, команда
`npm run test:fingerprint`.

Согласование Worker использует сохраняемый в BrowserContext паспорт и патч
`patches/playwright-core@1.63.0.patch`. Устанавливайте зависимости через
`pnpm install --frozen-lockfile`: `patchedDependencies` применяет патч к точной
версии Playwright. При отсутствии адаптера создание мобильного контекста
завершается ошибкой `worker_passport_adapter_unavailable`.

Инициализация выполняется до первой инструкции Worker, в штатной точке
возобновления Playwright. Для создания окружения и загрузки модульных зависимостей
используется временная остановка перед выполнением первого скрипта; после
применения паспорта отладчик отключается. DedicatedWorker, SharedWorker и
ServiceWorker получают нативный CDP User-Agent override и метаданные Client Hints.
CPU, память, языки и параметры WebGL эмулируются в соответствующем WorkerGlobalScope.
Настройки принадлежат BrowserContext и не переносятся между профилями.
Перезапуск и обновление ServiceWorker повторяют инициализацию нового окружения.
SharedWorker и ServiceWorker в проверенном Chromium не отправляют HTTP Client Hints на каждом
fetch: отсутствие заголовка учитывается как нативная возможность движка;
значения `navigator.userAgentData` проверяются независимо.

Новые паспорта содержат `fingerprint.canvas: {version: 1, mode: "native"}`.
Canvas и OffscreenCanvas читаются и экспортируются самим браузером, без шума
из seed и без обёрток Canvas от Orbit. При одинаковом изображении в одном
runtime смена seed не меняет пиксели. Это результат серверного Chromium,
а не эталон Android GPU. Другие версии браузера, драйверы, шрифты и изображение
могут изменить результат; общего гарантированного хеша модели телефона нет.

Старые паспорта без canvas-политики сохраняют `legacy-seeded-v1`: прежний seed,
попиксельное изменение и результат HTMLCanvas. Обновление не пересоздаёт их
идентичности. Политика новых паспортов включена в `identityHash`, её смена
изменяет идентичность. Валидатор поколения 6 требует явно сохранённый native-режим.

Матрица версии 3 измеряет MAX_VERTEX_UNIFORM_VECTORS,
MAX_FRAGMENT_UNIFORM_VECTORS, MAX_VARYING_VECTORS, MAX_TEXTURE_IMAGE_UNITS,
а для WebGL2 также uniform components и bindings. Проверяется
getShaderPrecisionFormat для двух стадий и шести float/int форматов.
Значения сравниваются между главным документом и остальными пятью контекстами,
включая OffscreenCanvas. Неподтверждённые параметры чипов не подставляются.

Пять лимитов каталога остаются эмуляцией: evidence.status = emulation,
measuredAt = null. Остальные лимиты и точность шейдеров принадлежат установленному
браузеру. В отчёте `graphics` явно указаны источники и `deviceDumpVerified: false`.
Лимиты эмуляции не увеличивают физическую ёмкость графического драйвера.
Проверки: `tests/native-canvas-cohort.test.mjs`, `tests/canvas-consistency.test.mjs`,
`tests/context-matrix.test.mjs`; сохранённые паспорта проверяются без миграции.

### Поведение API и контрольный браузер

`worker/api-behavior.mjs` измеряет дескрипторы и функции Navigator/UAData,
WebGL, HTMLCanvas/OffscreenCanvas, ClientRects, AudioContext/AudioBuffer и
FontFaceSet. Сохраняются имя/арность/собственные свойства функции, результат
`Function.prototype.toString.call`, поведение пустого Proxy, вызов с неправильным
receiver, конструирование и нормализованный стек ошибки. Асинхронные отказы
обрабатываются отдельно; сам диагностический скрипт не меняет прототипы.
Измерение выполняется во всех шести контекстах матрицы. Отсутствие API в Worker
не приравнивается к его неисправности.

`worker/native-baseline.mjs` создает контрольный контекст без скриптов профиля
Orbit в том же живом Browser. Кэш привязан к объекту Browser, а не только к номеру
Chromium; неудачное измерение не кэшируется. Общие плагины и флаги запуска могут
сохраняться: область сравнения явно указана в `baselineScope`. Базовый контекст
закрывается после измерения, ServiceWorker и диагностические маршруты очищаются.

Для более строгой проверки есть отдельная команда, не читающая рабочую БД:

```
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chrome pnpm profiles:audit ./prepared/profile-runtime.json
```

Она запускает два экземпляра одного бинарника с одинаковыми параметрами:
чистый Playwright без production-плагинов и обычный движок Orbit с ними.
Проверяются все десять шаблонов по два раза. Отчет содержит контрольные измерения,
различия каждого контекста и `nativeBehaviorConfirmed`. Ошибки измерения или
несоответствие паспорту дают ненулевой exit code. Наблюдаемые различия функций
сохраняются как находки, а не подменяются заявлением об успешной нативности.
Встроенная квалификация также сохраняет сводку и контрольные данные. Код новых
проверок входит в ключ квалификации и инвалидирует прежнее одобрение адаптера.

Различайте `contextMatrix.status` (значения соответствуют паспорту) и
`contextMatrix.apiBehavior.status` (`matched`, `differences`, `incomplete`).
Оба результата видны в паспорте качества. Поведение API остается диагностическим:
включение новой проверки не удаляет профили и не меняет их идентичность или допуск.
`matched` означает совпадение выполненных выборочных проверок, а не доказательство
неотличимости от реального Android или прогноз решения сторонней защиты.

Worker-адаптер сохраняет оригинальный getter, когда значение уже согласовано с
паспортом нативной эмуляцией CDP. Остальные необходимые JS-подмены не маскируются
новым глобальным `toString`: диагностика продолжает фиксировать их отличия.

Квалификация отдельно испытывает `Emulation.setHardwareConcurrencyOverride`
в изолированной странице и DedicatedWorker. Успешный ответ CDP не доказывает
распространение настройки на Worker. В локальном Chromium 154 основной поток
возвращал заданные 7, DedicatedWorker — реальные 4; поэтому CPU-подмены не удалены
для всех контекстов. Даже совпадение этих двух проб не квалифицирует SharedWorker
и ServiceWorker, что явно указано в `safeToReplaceAllCpuWrappers: false`.

Шрифты проверяются по FontFaceSet и метрикам Canvas относительно fallback,
включая Worker FontFaceSet, где доступен. Эта проверка не устанавливает шрифты
на сервер и не подтверждает набор шрифтов физического смартфона.

Полный перенос Canvas/WebGL/шрифтов в собственный Chromium требует исходников
выбранного движка, воспроизводимой сборки, обновлений безопасности и повторной
квалификации всех контекстов. Исходников Chromium в этом репозитории нет;
JS-инжектор этим изменением не заменен бинарным патчем. Перед таким переносом
нужно выбрать основу сборки и подтвердить контракт нативного ядра измерениями.

Тесты: `tests/api-behavior.test.mjs`, `tests/profile-quality-presentation.test.mjs`.

### Нативное хранение и HTTP-кэш

Новые партии создаются с `storageMode: persistent`. Существующие snapshot-профили
не переключаются автоматически: cookies/localStorage/IndexedDB можно перенести
при первом включении нативного режима, но отсутствующую историю HTTP-кэша и HSTS
из JSON восстановить нельзя. Паспорт и его хеш не изменяются при смене режима.

`persistent-profile.mjs` копирует закрытый каталог current в отдельный run,
а не пересоздает его из JSON. При неудаче run удаляется, current остается прежним.
Сохранение через журнал и SQL-коммит сохраняет парность JSON и полного каталога.
HTTP Cache, Code Cache, Cookies, Network Persistent State, TransportSecurity,
Local State, Local Storage, IndexedDB, Service Worker и CacheStorage не очищаются.
Удаляется только явный список служебных каталогов GPU/shader/Crashpad.
Chromium самостоятельно вытесняет HTTP-кэш с бюджетом 50 МБ. Лимит данных вне
кэшей — 100 МБ; current и previous учитываются отдельно при подсчете места.

Стандартный Playwright отключает HTTP-кэш при маршрутизации. В патче точной
версии playwright-core 1.63.0 добавлен opt-in маркер orbit-persistent-cache-v1.
Он применяется только к нативным контекстам Orbit и сохраняет разрешенный
HTTP-кэш при установке/удалении маршрутов. Правила Client Hints, ограничения
навигации и обработки запросов остаются действующими. Обычные контексты
Playwright и snapshot-профили сохраняют прежнюю политику отключения кэша.
При отсутствии патча нативный контекст не создается с ложным обещанием кэша.

Диагностические ресурсы имеют Cache-Control: no-store. Для persistent-профиля
отчет о восстановлении содержит httpCache: native_allowed_unverified,
serviceWorkers: allowed_unverified, tlsResumption: not_verified. Это описание
политики; восстановление ресурсов конкретного сайта не аттестуется по одному
наличию файлов. TLS-тикеты не объявляются сохраненными между процессами.

Ручное восстановление persistent-профиля использует JSON previous и соответствующий
полный каталог previous с тем же snapshotId, затем публикует обе копии с новым id.
Если каталог отсутствует или его id не совпадает, возвращается HTTP 409; JSON
не накладывается на нативные данные другого сеанса. После восстановления допуск
снимается до новой проверки. Snapshot-профили сохраняют прежнее JSON-восстановление.

`tests/persistent-cache.test.mjs` проверяет реальный перезапуск Chromium,
сохранение свежего JS без повторного скачивания, If-None-Match для устаревшего JS,
cookies/localStorage/IndexedDB, регистрацию ServiceWorker и CacheStorage,
а также блокировку уже закэшированного документа. Отдельно проверяются
защищенные файлы, удаление служебных каталогов, отказ неудачного run и подбор
парной резервной копии. API-восстановление покрывает
`tests/profile-reliability-ui.test.mjs`; сбои SQL/публикации —
`tests/profile-publication.test.mjs`. Установка зависимостей — только по lock-файлу
с патчем (`pnpm install --frozen-lockfile`).
