# Client Hints

`worker/client-hints.mjs` формирует HTTP-заголовки и CDP payload из сохранённого
`fingerprint.navigator.userAgentData`. `buildHttpClientHints(passport)` выдаёт
три базовых заголовка; второй аргумент `true` добавляет расширенные поля.
Chromium отправляет расширенные поля нативно после Accept-CH; общий перехватчик
запросов в `createMobileContext()` отсутствует. Совместимый `clientHintHeaders()` сохраняет
нижний регистр имён и поддержку прежнего Sec-CH-UA-Full-Version.

`formatBrandList()` экранирует кавычки и обратные слеши; управляющие символы
и не-ASCII строки отклоняются согласно RFC 8941, раздел 4.1.6:
https://www.rfc-editor.org/rfc/rfc8941.html#section-4.1.6

`buildCdpUserAgentOverride()` используется в `prepareMobilePage()` для
Network.setUserAgentOverride. Payload также проверяется тестом с
Emulation.setUserAgentOverride без JS-инжектора. Платформа берётся из паспорта:
для текущих Android это `Linux armv81`, согласно уточнению пользователя.
Пустая разрядность старого паспорта сохраняется, новые local-v6 передают `64`.

Accept-Language читается без учёта регистра имени заголовка. CDP получает
список языков без q-весов: Chromium добавляет их самостоятельно, а передача
готовых весов приводит к удвоению q-параметров на редиректах. HTTP сохраняет
заголовок паспорта. При отсутствии заголовка используются языки navigator,
а не глобальная русская локаль. Сохранённые паспорта не изменяются.

Первичные extraHTTPHeaders дополнительно фильтруются initialProfileHeaders():
`User-Agent` и все `sec-ch-ua*` исключаются без учёта регистра, включая базовые
и расширенные поля старого паспорта. User-Agent задаётся контекстом/CDP,
а дополнительные HTTP-заголовки остаются статическими.
Паспорт при этом не изменяется. Opt-in и Critical-CH обрабатывает Chromium;
Orbit не реализует собственный глобальный список Accept-CH. Проверка полного
контекста включает холодный запрос к двум origin и повторный запрос после Accept-CH.

Патч Playwright применяет метаданные отмеченного контекста в штатном
`_updateUserAgent` до первого запроса страницы, popup и фреймов. Это также
сохраняет полный Accept-Language паспорта: одной локали контекста недостаточно.
Обновление ServiceWorker использует те же метаданные. Наличие заголовков
Client Hints в fetch из Worker определяется самим Chromium; отсутствие
заголовка не заменяется принудительным extraHTTPHeaders.

Первый скрипт устанавливаемого ServiceWorker загружается браузерным процессом
до появления worker CDP-сессии. Для dedicated persistent-контекста
`persistentLaunchOptions(launchOptions, profile)` задаёт `--user-agent` уже при
старте Chromium, в том числе после синхронизации версии браузера и при проверке
перезапуска. Квалификация persistent-режима использует отдельный временный браузер
без --user-agent: стартовый профильный UA влияет и на нативные brands, поэтому
контрольные измерения нельзя брать из этого процесса. Для отмеченных контекстов патч дополнительно включает браузерный
Fetch только для resourceType `Other`: Chromium классифицирует bootstrap именно
так. Запрос с `Service-Worker: script` сопоставляется с service_worker target и
его BrowserContext; перед отправкой меняется только User-Agent на значение
`orbitUserAgentOverride(context)`. Другие Other-запросы продолжаются без изменений.
Документы и обычные скрипты не перехватываются, Network.setCacheDisabled не
вызывается; HTTP-кэш документов и ресурсов сохраняется. Client Hints остаются
нативными. Непомеченные контексты сохраняют свой UA. Проверки loopback включают
snapshot/persistent, параллельные контексты с разными UA, замену скрипта ServiceWorker,
закрытие контекста и кэшируемые документы; bootstrap-проверки обязательны без TODO.
Это исправление ServiceWorkerNewScriptLoader: фоновая перепроверка уже известного
скрипта через ServiceWorkerSingleScriptUpdateChecker не видна браузерному Fetch.
В persistent её также покрывает стартовый --user-agent; для snapshot этот отдельный
путь не входит в проверку первоначальной загрузки.

Диагностические маршруты для `orbit-fingerprint.invalid` и `orbit-frame.invalid`
устанавливаются только на время проверки и удаляются через finally, включая
ошибку навигации или открытия popup. Они не остаются в рабочем контексте и
не отключают его HTTP-кэш. Для JSON-снимка кэш не сохраняется между процессами;
для persistent-каталога остаётся нативное хранение Chromium.
